# mermaid-rendering Specification

## Purpose

The mermaid-rendering capability provides automatic detection, asynchronous SVG rendering, dual-mode code switching, streaming protection, and error fallback for Mermaid diagrams in chat messages. This allows users to visually inspect workflows, architectures, and state machines generated by AI agents directly within the chat interface.

## Requirements

### Requirement: Automatic Mermaid diagram detection and rendering

The system SHALL identify ````mermaid` code blocks in Markdown content and asynchronously render them as SVG diagrams.

#### Scenario: Valid diagram rendering
- **WHEN** a message containing valid Mermaid diagram syntax is loaded and not streaming
- **THEN** the system SHALL render and display the SVG diagram instead of a raw code block

##### Example: Flowchart rendering
- **GIVEN** a Markdown block containing:
  ```mermaid
  flowchart TD
      A[Start] --> B[Finish]
  ```
- **WHEN** the message finishes streaming
- **THEN** the system SHALL produce an SVG element containing nodes "Start" and "Finish" with a directed edge

### Requirement: Diagram and code view switching

The system SHALL provide a toolbar allowing users to switch between the rendered SVG diagram and the raw source code view.

#### Scenario: Toggle between diagram and code view
- **WHEN** the user clicks the "Code" toggle button on a rendered diagram
- **THEN** the system SHALL hide the SVG diagram and display the syntax-highlighted source code

##### Example: Code toggle interaction
- **GIVEN** a rendered diagram view
- **WHEN** the code toggle button is clicked
- **THEN** the diagram element is hidden and the pre-code block becomes visible

#### Scenario: Toggle back to diagram view
- **WHEN** the user clicks the "Diagram" toggle button while in code view
- **THEN** the system SHALL hide the code view and display the SVG diagram

##### Example: Diagram toggle interaction
- **GIVEN** a source code view
- **WHEN** the diagram toggle button is clicked
- **THEN** the code block is hidden and the SVG diagram becomes visible

### Requirement: Streaming protection and deferred rendering

The system SHALL defer Mermaid diagram parsing and SVG rendering while a message is actively receiving stream deltas.

#### Scenario: Streaming message displays code skeleton
- **WHEN** a message containing a Mermaid block has its streaming status set to true
- **THEN** the system SHALL display the syntax-highlighted code block with a drawing indicator and SHALL NOT invoke SVG rendering

##### Example: Active streaming chunks
- **GIVEN** a message with `streaming: true` receiving `graph TD\n A -->`
- **WHEN** the message delta is processed
- **THEN** the element renders as a code block and no SVG rendering is initiated

#### Scenario: Completion triggers diagram rendering
- **WHEN** the message streaming status transitions from true to false
- **THEN** the system SHALL automatically initiate Mermaid rendering and replace the code skeleton with the SVG diagram

##### Example: Transition to complete
- **GIVEN** a message with a complete Mermaid block transitioning from `streaming: true` to `streaming: false`
- **WHEN** the streaming state updates
- **THEN** the system invokes `mermaid.render()` and renders the resulting SVG

### Requirement: Graceful fallback on syntax error

The system SHALL intercept Mermaid syntax parsing errors and fall back to the source code view without crashing the interface or injecting error DOM elements.

#### Scenario: Malformed syntax fallback
- **WHEN** a Mermaid code block contains invalid syntax that fails parsing
- **THEN** the system SHALL display the raw code block and show an error warning notice

##### Example: Unbalanced brackets in diagram syntax
- **GIVEN** a Mermaid code block with invalid syntax:
  ```mermaid
  graph TD
      A[Unclosed label --> B
  ```
- **WHEN** the system attempts to render the diagram
- **THEN** the system SHALL display the raw text and display an error warning notice

### Requirement: Dark theme visual consistency

The system SHALL initialize Mermaid with theme settings matching the effective application theme: dark settings (`theme: 'dark'`) when the effective theme is dark or cannot be determined, and light settings (`theme: 'default'` with light application color variables) when the effective theme is light. When the effective theme changes, the system SHALL re-initialize Mermaid with the settings for the new theme and SHALL re-render every diagram that is currently displayed.

#### Scenario: Dark theme configuration applied
- **WHEN** the Mermaid library is initialized while the effective theme is dark
- **THEN** the system SHALL apply dark mode with background, line color, and text colors matching the design system

##### Example: Theme initialization parameters
- **GIVEN** application theme variables with dark background `oklch(0.16 0.02 264)`
- **WHEN** `mermaid.initialize()` is executed
- **THEN** the configuration includes `theme: 'dark'` and `securityLevel: 'strict'`

#### Scenario: Light theme configuration applied
- **WHEN** the Mermaid library is initialized while the effective theme is light
- **THEN** the configuration SHALL include `theme: 'default'`, `themeVariables.darkMode` equal to `false`, a light background, and `securityLevel: 'strict'`

#### Scenario: Unknown theme defaults to dark
- **WHEN** the configuration is built in an environment where no effective theme can be read
- **THEN** the configuration SHALL be the dark configuration

#### Scenario: Displayed diagrams redraw on theme change
- **WHEN** a rendered Mermaid diagram is visible and the user switches the theme from dark to light
- **THEN** the system SHALL re-render that diagram with the light configuration, and the diagram toolbar and container SHALL use light-theme colors

##### Example: Streaming diagram is not rendered by a theme change
- **GIVEN** a Mermaid block whose message is still streaming
- **WHEN** the theme changes
- **THEN** the system SHALL NOT invoke SVG rendering for that block until streaming completes

### Requirement: Code copy and lightbox inspection

The system SHALL support copying the raw Mermaid source text to the clipboard and expanding the diagram into a lightbox modal.

#### Scenario: Copying diagram source
- **WHEN** the user clicks the copy button on the Mermaid toolbar
- **THEN** the system SHALL copy the raw Mermaid source code to the clipboard and show confirmation visual feedback

##### Example: Clipboard copy action
- **GIVEN** a diagram with source text `graph TD; A-->B;`
- **WHEN** the copy button is clicked
- **THEN** the text `graph TD; A-->B;` is copied to the clipboard and the copy icon shows checked state

#### Scenario: Expanding diagram in lightbox
- **WHEN** the user clicks the zoom button or diagram container
- **THEN** the system SHALL open the diagram in the lightbox overlay for detailed inspection

##### Example: Lightbox trigger
- **GIVEN** a rendered Mermaid SVG element
- **WHEN** the zoom button is clicked
- **THEN** the lightbox modal opens displaying the SVG content
