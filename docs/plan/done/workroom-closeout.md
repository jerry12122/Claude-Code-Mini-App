# 工作室結案

已驗收整合（2026-11-19）：#44 的 db/mcp/server/arch、build/vet 與 skill 格式檢查通過；主樹整合後 db/ws/server/mcp/arch 全套、build/vet 再通過。原啟動、額度與精簡上下文規則已比對保留，canonical skill 已安裝。正式服務尚未重啟，每輪注入與薄工具仍待正式服務載入新版；本次沒有對真實工作室執行結案、重置或刪除。這份功能計畫歸檔不代表目前工作室已結案。

入口是對 PM 說「準備結案」或「結案並關閉」。沒有新的畫面、確認碼或定時續命。MCP 只提供能力，確認留在 supervisor-workflow。

## 生命週期

執行 → PM 驗收 → 保存成果與版本／有效證據 → 待結案確認 → 使用者對當下清單明確確認 → 才清理或關閉 → 回報。

CLI done、執行者回報完成、同意實作、沉默或舊清單，都不是這次清理的授權。建立本流程本身也不授權清理真實工作室。

## 確認後的順序

1. 停掉本任務的臨時服務。
2. 專用執行者只做重置或刪除其中一個。共用或不确定的會話保留。
3. 只移除已保存成果、沒有未保存改動、且已整合的本任務工作樹。
4. 最後刪除或關閉這個工作室。

不刪共用會話、其他工作室、使用者的正式服務或 repository。重置只清 Mini App 的續接、訊息、佇列與待處理，不清 provider 本機歷史或帳戶額度。任一步失敗就留下剩餘清單，不擴大範圍。PM 自己若要被重置或刪除，先保存回報，由使用者做最後一步。

## 工具

工作室 MCP（現任 PM、這一間）新增：

- `room_delete`：刪成員關係、備忘、派工與工作室佇列。session 與歷史留下。
- `reset_session`：只接受僅屬於這一間的會話。連上該會話的 WebSocket，等 `reset` 事件才回 ok。DB 狀態、記憶體中的 agent／shell 任務、待授權、待回答與 Shell 確認，都要在 dispatch 鎖內、取消或寫入之前仍是閒置。檢查後才開始的任務、變成共用，或 PM 已換人，都回失敗且不清資料。一般介面的 `reset_context` 仍是明確取消。

全域 `/mcp` 不提供這兩個工具。工具裡沒有確認策略。

每輪提醒由 skill 的 `references/pm-core.md` 維護。產品只在現任 PM 的 runner prompt 前面附上這份短檔；缺檔時留下診斷，不把規則寫進程式。角色以資料庫的現任 PM 為準。交接提交後的接任首輪另帶 room、skill 位置與版本；之後恢復短提醒。失敗的交接不發通知，也不另外啟動或重置會話。
