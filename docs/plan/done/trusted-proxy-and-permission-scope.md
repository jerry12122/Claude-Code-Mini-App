# 可信代理與授權範圍提示

日期：2026-10-06

## 實作

- 新增可選 `web.trusted_proxies` CIDR 清單，預設 `127.0.0.1/32`、`::1/128`，沿用同機 cloudflared 的來源判斷。明確設 `[]` 可停用轉發標頭。
- 使用 Fiber 的直連來源與可信代理檢查；只有可信代理可提供 `CF-Connecting-IP`／`X-Forwarded-For`。代理須覆寫 CF 標頭或在 XFF 尾端附加來源。
- XFF 從右往左跳過可信代理，在第一個不可信 IP 停下，避免採用客戶端偽造的最左側標頭。無效來源回空值，不能回退成代理的內網 IP 通過白名單。
- 舊 Claude denial 的即時與重連授權訊息帶 `retry_tools: true`，前端顯示「允許工具並重試」，說明只在本次重試放行工具、不限定畫面中的單一操作。
- Claude prompt-tool／Kiro ACP 中途授權維持「允許此操作」。不更動既有放行行為、不新增授權引擎或資料庫欄位。

## 驗證範圍

- auth：直連偽造標頭、內網不預設受信任、同機 CF／XFF、IPv6、XFF 偽造前綴／代理鏈、明確代理、空清單與無效來源。
- config：舊設定的 loopback 預設值、明確空清單與自訂代理。
- WebSocket：舊 denial 即時／重連都帶工具放行範圍，互動式授權即時／重連不帶。
- 真實 Tunnel、TG WebView 與 Claude CLI 端到端流程仍需實機驗證；本輪不重啟使用者正在執行的服務。

本輪檢查通過：`go test ./...`、`go vet ./...`、server／desktop build、兩個修改的前端檔案經 Babel 轉換與 JavaScript 語法檢查。檢閱了代理鏈解析、空設定、無效標頭、授權重連與前端狀態更新，未發現阻擋提交的問題。
