# 分頁釘選規劃

狀態：已實作並通過下列自動驗證。日期：2026-11-16。

目標：讓常用的會話分頁固定在各窗格左側，並避免整理分頁時誤關。沿用現有分頁 reducer、選單與 localStorage，不增加套件或後端 API。

## 參考與範圍

[VS Code 官方 Pinned tabs 說明](https://code.visualstudio.com/docs/configure/custom-layout#_pinned-tabs)提供的核心行為：釘選分頁排在一般分頁之前、不隨一般分頁捲走，且批次關閉會保留。VS Code 另有 normal／shrink／compact 尺寸及獨立一列選項。

本專案第一版採單列、保留名稱的固定寬度樣式，接近 shrink；不增加尺寸設定、獨立第二列或全域釘選快捷鍵。釘選不是預覽分頁／保持開啟模式，也不代表會話持續執行。

側欄的 `session.pinned` 已是伺服器上的會話釘選。這次新增「分頁釘選」，兩者獨立：分頁操作不改側欄排序，側欄釘選也不自動開啟或釘選分頁。選單明確使用「釘選分頁／取消釘選分頁」。

## 操作規則

| 操作 | 結果 |
| --- | --- |
| 一般分頁右鍵 → 釘選分頁 | 放到該窗格釘選區末端；保持目前作用中分頁，不因右鍵操作切換會話 |
| 已釘選分頁右鍵 → 取消釘選分頁 | 放到一般區最前端，不嘗試還原釘選前索引 |
| 點擊已釘選分頁的圖釘 | 取消釘選；不關閉、不切換會話 |
| 已釘選分頁的中鍵、Delete、桌面 Ctrl/Cmd+W、Alt+B、連按 Escape | 不關閉；作用中分頁不變 |
| 已釘選分頁右鍵 → 關閉分頁 | 停用，顯示「請先取消釘選」 |
| 關閉其他／右側／閒置分頁 | 僅關閉符合條件的一般分頁，釘選分頁一律保留；無可關閉目標時停用 |
| 新開會話或從側欄拖入未開啟會話 | 預設未釘選，加入一般區；不能插到釘選區中間 |
| 在同一窗格拖曳排序 | 釘選只能排在釘選區，一般只能排在一般區；跨越邊界時將插入位置限制到合法邊界，不自動切換釘選 |
| 移到另一窗格、拖到邊緣分割 | 保留釘選狀態，依目標區域插入；未指定位置時加入對應區域末端 |
| 合併窗格 | 先列出窗格 0、窗格 1 的釘選分頁，再列出兩窗格的一般分頁，各區內保持原順序 |
| 重新整理／重開桌面程式 | 還原開啟分頁、釘選狀態、順序與作用中分頁 |
| 實際刪除會話／既有 clear 重設流程 | 移除對應分頁及釘選紀錄；釘選不阻止刪除或重設 |

「先取消釘選才能關閉」是本專案的防誤關政策，不宣稱逐項複製 VS Code 的所有關閉設定。一般關閉應在 reducer 集中保護，避免漏掉快捷鍵入口；`prune`／`clear` 是資料移除或重設，不走這項保護。

分頁關閉只影響顯示，沿用目前的會話與草稿生命週期，不新增停止 agent 或刪除資料的行為。

## 呈現與鍵盤操作

```text
| [Agent 常用會話 📌] [Agent 規格討論 📌] | [Agent 臨時會話 ×] [Agent 測試 ×] → |
|              釘選區                   |              一般區               |
```

- 兩區位於同一列，仍是一個有名稱的 tablist；DOM 順序就是視覺及鍵盤順序，不只用 CSS `order` 調換。
- 釘選分頁寬度先採 144px，名稱省略但保留完整可存取名稱、agent 圖示、狀態與既有提示資訊；圖釘取代關閉鈕，不改作用中狀態線。
- 有一般分頁時，釘選區最多使用分頁列 50% 寬度；超出時釘選區自行水平捲動，一般區獨立捲動。全為釘選時可使用整列，零釘選時不保留空區。
- 捲動一般區不移動釘選區。分頁過多時不承諾所有釘選同時可見；操作任何分頁時，只將其所在區捲到可見，不帶動整頁或另一區。
- 沿用目前方向鍵、Home／End 與單一作用中 tab 的 roving tabindex，跨越兩區時仍依完整 `tabs` 順序導覽。釘選／取消後以 session ID 找回同一分頁，保持鍵盤焦點。
- 沿用既有 Shift+F10／選單鍵開啟右鍵選單，鍵盤可完成釘選與取消；不依賴圖示或滑鼠 hover。以輔助描述傳達「已釘選」，不誤用 `aria-selected` 表示釘選。
- 圖釘的可點擊範圍至少 24×24 CSS px；分頁按鈕與圖釘不可巢狀互動。圖釘作為滑鼠捷徑時，鍵盤／輔助技術仍由選單提供相同行為，不向 tablist 插入額外非 tab 鍵盤停靠點。
- 分頁釘選入口限現有桌面分頁列（≥1024px）。窄螢幕沿用目前導覽，不清除釘選資料；返回／切換窗格不得因釘選而無法離開畫面。

## 狀態與整合方式

維持群組的 `tabs: string[]` 與單一會話只出現在一個群組的規則，在分頁狀態最外層增加：

```js
{
  groups: [{ tabs: ['A', 'B'], active: 'B' }],
  pinnedTabs: ['A'],
  focused: 0,
  orientation: 'horizontal',
  ratio: 0.5
}
```

`pinnedTabs` 僅表達成員資格，顯示順序以各群組的 `tabs` 為準。因會話分頁全域唯一，不需要每群組另建一份釘選狀態，也不改 `tabs` 成物件陣列。

1. 新增 `pin`／`unpin` reducer action，對未知或已符合狀態的 ID 不動作；釘選後穩定調整群組陣列，保持釘選在前、一般在後。
2. `open`／`move` 的插入索引按釘選邊界限制；`splitDrop`／`toggleSplit` 保留成員資格並維持分區順序。拖曳指示線必須與 reducer 最後接受的位置一致，不能顯示在非法位置再跳回。
3. `close` 遇到釘選直接回傳原狀態，所有一般關閉入口共用；UI 批次操作先過濾釘選，據實計算停用狀態。`prune`／`clear` 清理對應紀錄。
4. 沿用 `miniapp_tab_groups_v1`，序列化加上選填的 `pinnedTabs`；舊資料缺欄位視為空陣列。讀入時只保留字串、去重、剔除不在開啟分頁內的 ID，再穩定分區。
5. 儲存失敗沿用目前降級為本次頁面記憶體的行為。釘選不承諾跨裝置同步。

注意：現有 reducer 的 `move`／分割合併／`prune`，以及序列化會重建群組或欄位，必須逐一檢查；不能只在 UI 排序，否則重新整理、合併或拖曳後順序會不一致。

## 實作順序與驗收

- [x] 先補 reducer／儲存回歸案例，再完成狀態邏輯與關閉保護。
- [x] 接上既有選單與圖釘，確認與側欄會話釘選互不影響。
- [x] 完成單列雙捲動區、拖曳邊界及跨區鍵盤焦點。
- [x] 跑 `node --test scripts/tab-groups.test.cjs scripts/console-usability.test.cjs scripts/landmarks-tabs-a11y.test.cjs`；檢查相關既有關閉選單測試，再跑 `node --test scripts/*.test.cjs`。
- [ ] 在桌面／瀏覽器手動驗證下表，並確認每窗格仍僅掛載目前作用中的 ChatView。

| 驗收案例 | 預期 |
| --- | --- |
| A、B、C，作用中 A，釘選 C 再釘選 B | 順序 C、B、A，作用中仍為 A |
| C、B 為釘選，取消 C | 順序 B、C、A；C 在一般區首位 |
| 對釘選使用中鍵／Delete／既有關閉快捷鍵 | 分頁保留，沒有誤關鄰頁；瀏覽器 Ctrl+W 仍由瀏覽器處理 |
| 混合 running、idle、未知狀態，再執行三種批次關閉 | 釘選全保留；一般分頁仍依原條件判斷，停用狀態與可關閉集合一致 |
| 同區拖曳、跨區拖曳、從側欄拖入、跨窗格移動 | 合法排序、指示位置正確、不隱式釘選或取消、不重複開啟 |
| 釘選分頁分割再合併、移出來源群組最後一頁 | 狀態與順序保留，空群組正常收合 |
| 釘選數量超過半列、全部釘選、零釘選 | 各分頁仍可透過捲動及鍵盤到達；一般區不被擠掉 |
| 鍵盤從選單釘選／取消後導覽到另一區 | 焦點不掉到 body，完整名稱與釘選狀態可讀，沒有額外 tab 停靠點 |
| 舊 localStorage、非法釘選 ID、重複 ID、重整 | 舊資料相容，非法紀錄被清理，排序及 active 正確還原 |
| 刪除已釘選會話、clear、縮至手機再放大 | 無幽靈釘選；導覽可離開；未被重設的釘選仍保留 |
| 淺／深色、高對比及減少動態效果 | 圖釘、作用中標記與焦點可辨識，不靠顏色單獨傳達狀態 |

第一版不做跨裝置同步、釘選數量上限、拖過邊界自動釘選、全域組合鍵或顯示模式設定。待實際有使用需求再擴充。
